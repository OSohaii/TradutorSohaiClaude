# Studio interactivity fixes: toolbar dedup, state lifting, tool wiring

This change fixes six issues left over from the Studio redesign. MangaViewer gains `hideInternalToolbar` and `embedded` props so the Studio can suppress its built-in toolbar and share zoom/edit/paint state through the Zustand store. RightPanel's tool grid becomes interactive and connected to `activeTool` in the store, the opacity slider loses its `pointer-events-none` block, and StudioToolbar gains zoom controls and edit/paint mode toggle buttons. StudioPage drops the underscore prefixes on auth-modal props.

**Watch for:** The auth-modal props (`onOpenIchigo`, `onOpenTorii`, etc.) are now destructured without underscores but still never used in the component body — this will fire lint/TS unused-variable warnings (confirmed). The opacity slider is now interactive but writes to local state that never reaches MangaViewer or anything visual (confirmed). The `activeTool` in the store and the edit/paint mode flags can drift out of sync when mode toggles in StudioToolbar are used instead of the RightPanel tools grid (confirmed).

## High-level view

State was lifted from MangaViewer's local `useState` into `useStudioStore` for zoom, editing mode, and paint mode. When MangaViewer renders in `embedded` mode it reads and writes to the store rather than its own state, allowing the StudioToolbar and RightPanel to control the viewer. The indirection uses an `effective*` pattern — local vars that pick between local state and store state depending on the `embedded` flag.

The RightPanel tool grid went from decorative (opacity-60, pointer-events-none) to functional. Each tool button now calls `handleToolClick`, which sets `activeTool` and also toggles `isEditingMode`/`isPaintMode` as appropriate. The StudioToolbar also gained edit/paint toggles that write to the same store fields but do not update `activeTool`, meaning the two control surfaces can disagree about what tool is active.

The StudioPage auth-prop fix removes underscore prefixes but doesn't wire the props to anything, converting them from intentionally-suppressed-unused to actually-unused — which will trigger lint failures.

## State synchronization between toolbar, tools grid, and viewer

The store holds `activeTool`, `isEditingMode`, and `isPaintMode` as independent fields. RightPanel's `handleToolClick` keeps them in sync: selecting "brush" sets `activeTool='brush'`, `isPaintMode=true`, `isEditingMode=false`. But StudioToolbar's edit-mode toggle does `setIsEditingMode(!isEditingMode); setIsPaintMode(false)` without touching `activeTool`. After toggling edit mode from the toolbar, `activeTool` might still read `'brush'` while `isEditingMode` is true — the tools grid highlights "brush" while the viewer is in editing mode.

The fix is straightforward: StudioToolbar's mode toggles should also call `setActiveTool` with the corresponding tool ID (`'select'` for editing mode, `'brush'` for paint mode), or the store should derive `isEditingMode`/`isPaintMode` from `activeTool` rather than storing them independently.

## Unused auth-modal props in StudioPage

Before this change, the five `onOpen*` props were prefixed with `_` to satisfy no-unused-vars:

```tsx
onOpenIchigo: _onOpenIchigo,
```

Now they're simply destructured as `onOpenIchigo` etc., but nothing in the component renders or passes them. This will produce five TypeScript or ESLint warnings. The intent was likely to stop ignoring them and wire them to a settings menu or modal trigger, but that wiring isn't present in this diff.

## Opacity slider: interactive but disconnected

The slider's `pointer-events-none` and `opacity-70` wrapper were removed, making it draggable. The state it writes to (`const [opacity, setOpacity] = React.useState(100)`) is local to RightPanel and never propagated. To make it functional, opacity would need to reach MangaViewer (either via the store or as a prop) and be applied as a CSS opacity on the translated-text overlay or the canvas layer.

## Unconditional store subscriptions in MangaViewer

```tsx
const storeZoom = useStudioStore(s => s.zoom);
const storeSetZoom = useStudioStore(s => s.setZoom);
// ... 4 more
```

These subscriptions run regardless of the `embedded` prop. When MangaViewer is used standalone (e.g., in the reader view), every change to `useStudioStore` triggers a re-render via these selectors, even though the `effective*` pattern discards the values. This is a performance concern: every zoom or mode toggle in an unrelated Studio instance re-renders all standalone viewers on the page. Conditionalizing the subscriptions (e.g., `useStudioStore(s => embedded ? s.zoom : null)`) would avoid this.
