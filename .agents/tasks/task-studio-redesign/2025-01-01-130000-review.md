# Multi-panel manga studio workspace

The StudioPage has been decomposed from a monolithic 2-panel component (sidebar thumbnails + viewer) into a 4-panel professional editing workspace: a 60px icon rail, a collapsible pages thumbnail grid, a central canvas wrapping MangaViewer, and a right editor panel with layers/tools/history tabs. A new Zustand store (`useStudioStore`) manages panel visibility and right-panel tab state. The visual treatment shifts to a dark cyberpunk aesthetic with glassmorphism, neon purple/blue accents, and framer-motion animations on every panel.

**Watch for:** Layer visibility and opacity controls are cosmetic only — they don't propagate to the actual rendering (confirmed). Navigation items in the left sidebar (Chapters, Tasks, Team, etc.) are dead-end click handlers (confirmed). No tests were added for the new store or any of the five new components (confirmed).

## High-level view

StudioPage becomes a thin composition root wiring Zustand selectors and callback props into four sub-components in `components/studio/`. The StudioPageProps interface is preserved exactly, though `onRetranslate` and `onTranslateImage` are underscore-prefixed and never passed down — those UI actions are now unreachable.

The Zustand store holds only UI layout state (panel visibility, active tab, selected layer). `selectedLayerId` and `activeRightTab` live in the global store but nothing outside RightPanel reads them, making them effectively component-scoped state with global persistence characteristics.

RightPanel's layer visibility toggle and opacity slider modify local state only — they don't feed back into MangaViewer's rendering. The tools grid (Texto, Selecao, Mover, Pincel, Borracha, Conta-gotas) is purely decorative with no tool selection state or effect on editing behavior.

LeftSidebar renders seven navigation items but only two (Dashboard, Library) trigger real actions. The remaining five create clickable icons that highlight on click but go nowhere.

## Disconnected layer and opacity controls in RightPanel

RightPanel maintains `hiddenLayers: Set<string>` and `opacity: number` in local React state. Neither value leaves the component. MangaViewer receives `currentImage.bubbles` directly from CentralCanvas with no filtering. The visual language (eye icon, slider with percentage readout) strongly implies these controls affect the canvas, which they don't.

```tsx
// RightPanel.tsx — local state, never exported
const [hiddenLayers, setHiddenLayers] = React.useState<Set<string>>(new Set());
const [opacity, setOpacity] = React.useState(100);
```

To make these functional, `hiddenLayers` could live in `useStudioStore` and be consumed by BubbleOverlay to skip rendering hidden bubbles. Alternatively, if planned for a future iteration, they should be disabled/greyed to signal "coming soon."

## Dead-end sidebar navigation

LeftSidebar's `handleClick` only fires `onGoToLibrary()` for two of seven items:

```tsx
const handleClick = (id: string) => {
  setActiveId(id);
  if (id === 'library' || id === 'dashboard') {
    onGoToLibrary();
  }
};
```

The remaining five set local state that highlights the icon but triggers no navigation. Since `useViewStore` only supports library/studio/reader views, these can't route anywhere yet. Interactive-looking items that do nothing erode trust in the interface.

## Props dropped during redesign

The original StudioPage consumed `onRetranslate` in a toolbar button and `onTranslateImage` in the thumbnail sidebar. The new version accepts both but discards them:

```tsx
const StudioPage: React.FC<StudioPageProps> = ({
  onRetranslate: _onRetranslate,
  onTranslateImage: _onTranslateImage,
  ...
}) => {
```

The "retranslate all" and per-image translate actions that existed in the old UI are now unreachable. The task findings say "the interface was preserved" but functionality was silently removed.

## Mobile panel toggle mismatch

All three side panels use `className="hidden md:flex ..."` — invisible below 768px. The toolbar's panel-toggle buttons are always visible and update store state, but on mobile the toggled panels never render. A user on a tablet in portrait can tap the pages-panel button, the store flips `pagesPanelOpen`, but nothing appears. The toggle buttons should either be hidden below `md` or the panels should present as overlays/drawers on mobile.

## Bundle size growth

Bundle grew from 375KB to 522KB (gzipped 104KB to 151KB) — a 45% increase, mostly from framer-motion. The animations used here are lightweight hover scales and panel width transitions that could be achieved with CSS transitions and Tailwind's `hover:scale-105`. Not blocking, but notable for users on slower connections.
