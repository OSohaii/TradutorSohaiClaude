# Multi-panel manga studio workspace (v2)

The v2 pass addresses three of the six concerns raised in v1: `onRetranslate` and `onTranslateImage` are now wired through CentralCanvas into StudioToolbar with functional UI buttons, dead sidebar navigation items are visually dimmed with "Em breve" tooltips, the layer visibility toggle and opacity slider are labeled "(preview)" to set expectations, and panel toggle buttons are hidden below the `md` breakpoint. The remaining v1 concerns — no test coverage and six unused modal-opener props — persist but are lower severity.

**Watch for:** The six provider-modal props (`onOpenIchigo`, `onOpenTorii`, `onOpenDeepL`, `onOpenGemini`, `onOpenOpenAI`, `onOpenFonts`) are still declared in the interface but silently dropped — there's no UI surface to trigger them (confirmed). No test coverage for the five new components or the store (confirmed). Tools grid in RightPanel remains purely decorative with no selection state or "(preview)" label (confirmed).

## High-level view

The prop-wiring fix routes `onRetranslate` and `onTranslateImage` from StudioPage through CentralCanvas into StudioToolbar, where they render as "Retraduzir" and "Traduzir" buttons gated by image status.

The dead-navigation fix uses an `enabled` flag on each navItem, rendering disabled items at 50% opacity with `cursor-not-allowed` and "Em breve" in both title attribute and hover tooltip. Clicking a disabled item is a no-op.

The "(preview)" labels on layer visibility and opacity controls communicate non-functional status, but the controls still accept interaction (toggle, drag) with no visible effect on the canvas — the slider value updates, the eye icon toggles, nothing changes in the viewer.

Six provider-modal props are accepted by the StudioPageProps interface but never destructured. There's no path to open provider settings from within the studio — a user who wants to configure DeepL, Gemini, or fonts must leave the studio view.

## Provider-modal prop gap

StudioPage's interface declares all six modal-opener props for interface compatibility, but the component destructures only `onOpenSettings`:

```tsx
const StudioPage: React.FC<StudioPageProps> = ({
  onOpenSettings,
  onRetranslate,
  onTranslateImage,
  onTranslateOnly,
  onCancelOcr,
  onRetryImage,
}) => {
```

No gear menu, context menu, or toolbar item invokes `onOpenIchigo` through `onOpenFonts`. The old UI exposed these through a provider-switcher dropdown; the new UI has only a single settings gear that routes to `onOpenSettings`. A user who wants to configure DeepL, Gemini, or fonts must leave the studio view entirely.

## Tools grid without "(preview)" signaling

The six tool buttons in the Editor tab render interactive-looking UI:

```tsx
<div className="grid grid-cols-3 gap-1.5">
  {tools.map((tool, idx) => (
    <button key={idx} className="... hover:bg-purple-500/10 ...">
```

They respond to hover with purple highlight, have descriptive labels, and use recognizable tool icons. Unlike the layer section (which now shows "(preview)") and the opacity slider (which shows "(preview)" and is dimmed), the tools section has no indication these are placeholders.

## Interaction on inert controls

The opacity slider and layer eye toggles still accept user input. Dragging the slider updates the `opacity` state (visible in the percentage readout changing), and toggling the eye icon swaps between EyeIcon/EyeSlashIcon. The "(preview)" label communicates intent but doesn't prevent confusion when the slider value changes with no canvas effect. Either add `pointer-events-none` to fully disable them, or add a tooltip on first interaction explaining these are coming soon.
